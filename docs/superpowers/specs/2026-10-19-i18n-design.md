# Internationalisierung de-DE / en-US – Design

Stand: 2026-10-19 · Branch `claude/feature/i18n` · Grundlage: `.superpowers/sdd/i18n-research.md` (Konzept) und die Nutzer-Entscheidungen im Ledger `.superpowers/sdd/2026-10-19-i18n/progress.md`.

Shellherd bekommt eine vollständige zweisprachige Oberfläche: Deutsch (Quellsprache) und Englisch. Die Texte liegen als JSON-Kataloge im Repo, die Sprache folgt standardmäßig dem System und lässt sich live umschalten.

## 1. Umfang

**Drin (v1):**

1. i18n-Fundament mit i18next + react-i18next, statische JSON-Kataloge, Typsicherheit der Keys, Guard-Test.
2. Sprache als App-Einstellung „System / Deutsch / English“, persistiert in `userData/settings.json`, Main entscheidet, Broadcast an alle Fenster, Live-Umschalten ohne Neustart, erster Frame ohne Flackern.
3. Migration aller Oberflächentexte im Renderer (alle Komponenten, Hooks und Logik-Module).
4. Main erzeugt keinen Oberflächentext mehr: Fehler und Statusmeldungen als Codes, übersetzt im Renderer. Native Flächen (Fenstertitel, `dialog.*`) über eine eigene i18next-Instanz im Main.
5. KI-Assistent: System-Prompt nativ in der UI-Sprache.
6. Datum, Zahl, Sortierung und Suche über ein zentrales `src/shared/format.ts`.
7. Installer mehrsprachig (NSIS de/en), Release-Notes zweisprachig, englisches Handbuch `docs/manual.md`.

**Nicht drin:** weitere Sprachen, RTL, Pseudo-Lokalisierung, Extraktions-Tooling, ICU, Lazy-Loading, Sprache pro Fenster oder Vault, Sprachwahl-Dialog im Installer, Übersetzung von kubectl-artigen Ausgaben (`describe.ts`, `log-format.ts`, Alterangaben `12s/3m/2h/5d`, Rohstatus wie `Running`).

## 3. Architektur

### 3.1 Kataloge

```
src/shared/locales/
  index.ts                 Ressourcen-Index, NAMESPACES, resources (as const)
  i18n-catalog.test.ts     Guard-Test
  de-DE/  common app vault connection terminal kubernetes kubeActions
          containers files assistant workflows main .json
          errors/ ssh containers kubernetes files ai core .json
  en-US/  (identische Dateien und Keys)
src/shared/i18n.d.ts       CustomTypeOptions
```

- Namespaces (13): `common`, `app`, `vault`, `connection`, `terminal`, `kubernetes`, `kubeActions`, `containers`, `files`, `assistant`, `workflows`, `errors`, `main`.
- `errors` wird im Index aus den sechs Dateien gespreadet. Jede Datei hat genau einen Top-Level-Schlüssel gleich ihrem Dateinamen (`{ "ssh": { … } }`).
- Index und `i18n.d.ts` legt das Gerüst an, danach ändert sie niemand. Alle Katalogdateien existieren ab dem Gerüst als Skelett.
- `i18n.d.ts`:
  ```ts
  import type { resources } from './locales';
  declare module 'i18next' {
    interface CustomTypeOptions { defaultNS: 'common'; resources: (typeof resources)['de-DE']; returnNull: false }
  }
  ```
  Ein falscher Key bricht `npm run typecheck`.

### 3.2 Renderer

- `src/renderer/src/i18n.ts` initialisiert beim Import synchron: `resources`, `lng: initialLocale()`, `fallbackLng: 'de-DE'`, `defaultNS: 'common'`, `ns: NAMESPACES`, `initImmediate: false`, `interpolation.escapeValue: false`, `returnNull: false`. `initialLocale()` = `window.desktopApi?.initialLocale ?? 'de-DE'` (Vitest hat kein `window`). Setzt `document.documentElement.lang` und `setFormatLocale()` beim Start und bei `languageChanged`. Exportiert `i18n`, `t`, `useTranslation`, `Trans`.
- `main.tsx` importiert `./i18n` als ersten Projektimport und registriert `desktopApi.onLocaleChanged(l => i18n.changeLanguage(l))`.
- `App` und `SecondaryWindow` rufen `useTranslation()` an der Wurzel. Sprachwechsel rendert den Baum neu, ohne Remount (Terminals und Sitzungen bleiben).
- `src/renderer/index.html`: festes `lang="de"` entfällt (gesetzt durch `i18n.ts`).
- `src/renderer/src/error-text.ts`: `errorText(error: unknown, fallbackKey)` ersetzt die neun Kopien der IPC-Präfix-Regex und `getErrorMessage` (`App.tsx:100`).

### 3.3 Sprache im Main

- `src/shared/locale.ts`: `Locale = 'de-DE' | 'en-US'`, `LanguageSetting = 'system' | Locale`, `SUPPORTED_LOCALES`, `resolveLocale(setting, preferred: string[]): Locale` (vergleicht die Basissprache; `de-*` → de-DE, sonst en-US).
- `src/main/app-settings.ts`: `readSync(file)` beim Start (kaputte oder fehlende Datei = Defaults), `write(file, patch)` best effort, zod-geprüft, unbekannte Schlüssel bleiben erhalten. Datei `join(app.getPath('userData'), 'settings.json')`, Schema `{ language: 'system' | 'de-DE' | 'en-US' }`.
- `src/main/locale.ts`: `LocaleStore` mit `get()`, `set(setting)` (persistiert, benachrichtigt), `subscribe()`. Systemsprache aus `app.getPreferredSystemLanguages()` nach `whenReady`.
- `src/main/i18n.ts`: `createInstance` nur mit Namespace `main`, `mainT(key, params)`.
- `index.ts`: `createWindow` setzt den Titel über `mainT` und `additionalArguments: ['--shellherd-locale=<effective>']`. Bei Änderung: `setTitle` für alle Fenster und `webContents.send('app:locale-changed', { locale })` an alle Fenster.
- IPC (`shared/ipc.ts`): `app:get-language` → `{ setting, effective, system }`, `app:set-language` (zod `z.enum(['system','de-DE','en-US'])`, nur vom Hauptfenster), Event `app:locale-changed`. `DesktopApi` bekommt `initialLocale`, `getLanguage()`, `setLanguage()`, `onLocaleChanged()`.
- Preload: `initialLocale` aus `process.argv` (`--shellherd-locale=`), Default `'de-DE'`.

### 3.4 Fehlercodes

`CodedError = { code: ErrorCode; params?: Record<string, string | number>; detail?: string }` in `src/shared/errors.ts`.

1. **Geworfene Fehler** aus `ipcMain.handle`: `class AppError extends Error`, `message = encodeError(...)` im Drahtformat `§<code>` plus optional ` <json>` mit `params`/`detail`. `decodeError(message)` toleriert das Electron-Präfix `Error invoking remote method '…': (Error: )?` und gibt für Fremdtext `null` zurück.
2. **Ereignisse** (`SshEvent`, `SftpEvent`, `RdpEvent`, `KubeEvent.trouble`, `ClusterStatus`, `KubeProblem`, `AiEvent`): Feld `error?: CodedError` ersetzt `message?: string`.

- `ErrorCode` ist der Pfadtyp über `resources['de-DE'].errors`; `new AppError('ssh.keyFil')` ist ein Typfehler.
- Codes heißen `<area>.<camelCase>`. `detail` ist Rohtext aus Fremdbibliotheken, höchstens 500 Zeichen, nie Stack, nie Schlüsselmaterial.
- `errorText()`: `decodeError` → `t('errors:' + code, params)`, bei `detail` angehängt laut Katalogmuster; nicht dekodierbar → Präfix strippen, auf 500 Zeichen kürzen, roh zeigen.
- Main-Tests prüfen `AppError` und `.code`, nicht mehr Sätze.

### 3.5 KI-Assistent

`systemPrompt(context, locale)` liest die Zeilen aus `main:assistant.prompt.*`. Beide Sprachen sind nativ formuliert, nicht nur „Antworte auf Englisch“ angehängt. Die Locale kommt aus dem `LocaleStore`. Ebenso die Shell-Labels und der Verbindungstest (`assistant.ts:7-11,91,97`).

### 3.6 Formate

`src/shared/format.ts` mit `setFormatLocale(locale)`, `formatDateTime(value, 'short' | 'long' | 'time')`, `formatNumber(value, options?)`, `compareText(a, b)` (Collator `numeric: true, sensitivity: 'base'`), `foldCase(text)`; Instanzen je Locale gecacht. Ersetzt alle festen `'de-DE'`/`'de'` und alle nackten `localeCompare`/`toLocaleLowerCase()` (Fundstellen im Konzept 1.2).

### 3.7 Einstellung „Sprache“

`components/LanguageSetting.tsx` nach dem Muster von `FileTypeSetting` (`WelcomePage.tsx:63-84`): Label „Sprache“/„Language“ und ein `select` mit `System (Deutsch)` bzw. `System (English)` (aufgelöste Systemsprache), `Deutsch`, `English`. Sprachnamen sind Endonyme und werden nie übersetzt. Plätze: Startkarte unter `FileTypeSetting` (`App.tsx:904`) und Welcome-Seite „Gut zu wissen“. Nur im Hauptfenster. CSS: Selektor `.language-setting` an die bestehende Regel `.file-type-setting` anhängen; keine neuen Werte, keine Tokens, keine Bewegung.

## 4. Regeln für alle Tasks

- **R1** Text entsteht zur Laufzeit: Komponenten über `useTranslation()`, Logik-Module über `t()` innerhalb von Funktionen. Konstanten auf Modulebene tragen Keys oder Ids, nie Text.
- **R2** Shared importiert kein i18n. Main importiert nur `src/main/i18n.ts`, nur für native Flächen.
- **R3** Plural nur über `count` mit `_one`/`_other`-Keys, keine Ternäre.
- **R4** Sätze mit Markup nur über `<Trans i18nKey components={{ strong: <strong/>, code: <code/>, kbd: <kbd/> }}>`; keine Verkettung von Satzteilen.
- **R5** Keys sind semantisch (`terminal:closeTab.title`). Zugriff immer mit Namespace-Präfix, damit der Verwaisten-Check greift. Dynamische Keys werden als `as const`-Array deklariert.
- **R6** Typografie: de-DE „…“ und `…`, en-US “…” und `…`, nie `...`. Du-Imperativ ohne „Bitte“; en-US Imperativ ohne „please“.
- **R7** Nicht übersetzt: Terminalinhalt, Rohstatus aus Docker/Kubernetes, kubectl-artige Ausgaben, Marken- und Protokollnamen, Dateiendungen, Endonyme, Tastensymbole (`↑`, `Esc`, `F5`). Tastenwörter (`Strg`/`Ctrl`, `Umschalt`/`Shift`, `Leertaste`/`Space`, `Entf`/`Del`) kommen aus `common:keys.*`.
- **R8** Sortieren, Suchen und Formatieren nur über `format.ts`; kein `new Intl.*` außerhalb davon.
- **R9** Design-System gilt unverändert; `design-tokens.test.ts` bleibt maßgeblich.
- **R10** Bestehende Renderer-Tests bleiben unverändert grün (Setup auf de-DE). Wer eine deutsche Assertion ändern muss, begründet es im Report.
- **R11** Jeder Task schreibt nur seine eigenen Dateien und genau seine Katalogdatei(en) in beiden Sprachen.
- **R12** Glossar en-US: Vault = vault, Verbindung = connection, Bereich = pane, Ansicht = view, Reiter = tab, Fenster = window, Seitenleiste = sidebar, Dock = dock, Zugang = access host, Laufzeit = runtime, Gast = guest, „Dieser Computer“ = “This computer”, Sperren = Lock, Trennen = Disconnect, Entfernen = Remove, Löschen = Delete, Neu starten = Restart, Rollout neu starten = Restart rollout, KI-Assistent = AI assistant, Sitzung = session, Arbeitsbereich = workspace.

## 5. Guard-Test `i18n-catalog.test.ts`

- (a) Key-Parität de-DE ↔ en-US je Namespace (abgeflacht).
- (b) Platzhalter-Parität (`{{name}}`-Mengen gleich).
- (c) Keine leeren Werte.
- (d) Keine verwaisten Keys: voller Key `ns:a.b` oder Blattname als Literal in `src/**` (ohne Tests); `errors:`-Keys gelten als benutzt, wenn der Code (`ssh.keyFile`) im Main vorkommt.
- (e) `errors/<area>.json` hat genau den Top-Level-Schlüssel `<area>`.
- (f) Katalogwerte ohne `...`, ohne führendes „Bitte “/„Please “.
- (g) Ab dem Sweep: keine deutschen Literale (`[äöüÄÖÜß]` und JSX-Textknoten mit ≥ 2 Wörtern) in `src/renderer/**`, `src/main/**`, `src/shared/**` außer `locales/` und Tests. Ausnahme je Zeile per `// i18n-ignore`.

Regel (d) und (g) dürfen bis zum Sweep als `it.skip` bzw. als Warnung laufen, wenn die Migration noch unvollständig ist; der Sweep schaltet sie scharf.

## 6. Release-Notes

- `CHANGELOG.en.md` mit identischer Struktur (`## [x.y.z] – YYYY-MM-DD`, gleiche Zahl Aufzählungspunkte je Version), alle bisherigen Versionen übersetzt.
- `release-notes.ts` lädt beide Dateien per `?raw`, `releasesFor(locale)`; `ReleaseNotes.tsx` wählt nach `i18n.language`, Datum über `formatDateTime(…, 'long')`; `seenVersion` bleibt sprachunabhängig.
- `scripts/check-version.mjs` prüft beide Dateien. Paritätstest in `src/shared/version.test.ts` (liest per `fs`).
- `scripts/release-notes.mjs` gibt `## English` und `## Deutsch` aus.

## 7. Installer

```yaml
nsis:
  multiLanguageInstaller: true
  installerLanguages: [de_DE, en_US]
  displayLanguageSelector: false
```

## 8. Handbuch

`docs/manual.md` als englische Fassung mit gleicher Abschnittsfolge wie `docs/handbuch.md`. Beide verweisen oben aufeinander, die README verlinkt beide. `handbuch.md` und `manual.md` bekommen den Abschnitt „Sprache“/„Language“.

## 9. Tests

Automatisch: Guard-Test, `format.test.ts`, `errors.test.ts`, `error-text.test.ts`, `locale.test.ts`, `app-settings.test.ts`, `version.test.ts` (CHANGELOG-Parität), en-US-Tests für Umschalten, Fallback und Plural, alle bestehenden Renderer-Tests unter de-DE grün, Main-Tests auf `AppError.code`.

Vitest: neue `vitest.config.ts` mit `include: ['src/**/*.test.ts']` und `setupFiles: ['src/test/setup.ts']`; der Setup initialisiert i18n und Formate auf de-DE.

## 10. Manuelle Abnahme

1. Windows auf Englisch, Einstellung „System“ → erster Frame englisch, Titel richtig, Nebenfenster ebenso.
2. Umschalten bei offenen Terminals und Nebenfenster → beide Fenster wechseln live, Terminals laufen weiter, `settings.json` enthält `"language"`.
3. Schreibgeschützter Vault → Toast zeigt übersetzte Ursache.
4. SSH gegen `127.0.0.1:1` → Fehlermeldung in beiden Sprachen, Rohtext nur als Detail.
5. KI-Frage bei englischer UI → englische Antwort.
6. Dateibrowser: Datum/Größe in beiden Formaten, Sortierung `file2 < file10`.
7. Release-Notes-Dialog in beiden Sprachen.
8. Installer auf deutschem und englischem Windows ohne Sprachdialog.
9. Textlängen-Check Englisch: Kopfzeile, Tabs, Kontextmenüs, Hilfe-Overlays.

## 11. Folgen für UX-Audit v2

Das Audit wird nach diesem Branch umgesetzt. Seine neuen Texte gehören in die Kataloge (`terminal`, `app`, `common`, `errors:connection.*`), sein `connection-errors.ts` liefert Codes statt Sätzen, und die Audit-Regel U11 (keine `...`) ist bereits durch Guard-Regel (f) abgedeckt. Die Audit-Spec selbst wird in diesem Branch nicht geändert.
